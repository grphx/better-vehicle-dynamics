# Tire wear fix - in-game verification (2026-10-28)

Build 42.21.0, ZombieBuddy 2.3.4, BVD v0.1.18 candidate. Reported on the Workshop page: wheels "break" on
removal even with enough Mechanics skill, all wheels once one does, restart helps.

## Reproduction (v0.1.17, defaults)
`wheels` mode, Mechanics 10, fresh CarNormal, three launches from a standstill (about 7 s of driving):
- vehicle PART condition (mechanics window): 100 on all four, unchanged
- tire ITEM condition: 100 -> 0.0 on all four
- removal through the game's own uninstall routine: 4/4 succeeded, 4/4 came out broken (condition 0)
Control, same build with TireSlipWear off: items stayed 100, 0 broken.
Cause: BVD_RuntimeChecks.lua set the tire item's condition on every frame the throttle was down below 8 km/h.
`VehiclePart.setCondition` pushes into the item, not the other way round, and `transmitPartCondition` does
nothing on a client, so the part, the grip model and other players never saw it.

## Fix
Slip is counted on the driver's client (real time, stuck = throttle down and under 3 km/h for 2 s, 0.5 points/s
per driven tire at rate 1.0); the server (`server/BVD_TireWearServer.lua`) applies it to the two rear PARTS
(driver check, option check, cap 5 points, 0.9 s minimum interval) and transmits it. Option now defaults off.

## Results with the fix
- `wheels` (option on) SP: PASS 16/16 - counter 30 points per minute at 10/60/240 fps, nothing before the
  dwell, three ordinary launches wear nothing, counted slip wore both rear parts by 5 with the items following
  and the front untouched, a request sent twice wore 5 not 10, all four wheels removed unbroken at the
  mechanics-window condition.
- `wheels_off` (shipped default) SP: PASS 16/16, counted slip and wear requests change nothing.
- `sp` (plain regression): PASS 12/12.
- `mp` (dedicated server, two clients): client A PASS 13/13 incl. "server wore the rear tire part and sent it
  back" (rear 100 -> 95, front 100); client B PASS 5/5 incl. seeing the worn rear tire (95); server 0 errors.

## Not covered
- A car physically stuck in mud/snow (the stuck-speed threshold was raised in the test so a driving car counts).
- Wheels already removed broken stay broken; reload resetting still-installed items was inferred, not tested.
- Manual-install path (Lua-only change, same files for both paths).
