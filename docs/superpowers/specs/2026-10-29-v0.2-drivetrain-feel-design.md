# BVD 0.2 - drivetrain feel (design)

Status: draft for the owner. Written 2026-10-29 after a scan of the largest rival, Better Car Physics (BCP,
Workshop 2909035179: 176k subscribers against our 40k).

## Intent

BCP wins on how a car *feels* to drive (it keeps the car in gear when you lift off, brakes with the engine,
matches revs, slides on a bad downshift, has manual and semi-auto modes) and loses on install pain, class
conflicts, modded cars and server control. BVD already leads on grip, tyres, load, weather and server-side
settings. 0.2 closes the feel gap without giving up what BVD already does, and keeps every new behaviour a
sandbox option, because server control is the thing the rival cannot offer.

## What the audit found (BVD today, read from the controller source)

- **The drivetrain is one-way.** The engine turns the wheels (through a torque-converter model), but the wheels
  never turn the engine. Engine speed is integrated from throttle torque minus a friction term that depends only
  on RPM. Lift off at speed and the RPM falls to idle while the car keeps rolling; there is no engine braking,
  and a downshift does not raise the revs. This is the main gap and it is a contained change in the engine
  section of the controller.
- **RPM profile is two-valued.** Only `engineRPMType == "firebird"` changes anything (redline 6000, shift 5800);
  every other type, including the vanilla `van` and `jeep` ones, uses 4500/4350.
- **Manual mode exists** (tick box, shift up/down on the arrow keys, a reverse gear with an auto-reverse option)
  but is keyboard only, has no clutch or stall, and I found no gamepad handling anywhere in BVD's Lua.
- **An engine-sound system is already in the controller and is switched off.** It plays crank, start, engine and
  exhaust loops with pitch from engine RPM, but only for a vehicle that has an `engineSound` spec, and stock BVD
  ships none, so vanilla audio plays. Correction to my earlier scan note: the missing piece is sound assets and
  spec data, not engine code.
- Translations: EN, PL, RU. BCP has about nine.

## Goals

1. Lifting off keeps the car in gear and slows it with the engine; downshifting raises the revs to match.
2. A downshift into a gear far too low locks the driven wheels briefly and can slide the car.
3. Vans, sports cars and trucks behave differently, driven by the vehicle script's own `engineRPMType`.
4. A player can tell which install path they are on (ZombieBuddy, manual, none) without reading the log.
5. More languages.
6. Stretch: engine sound through the dormant system.

## Non-goals and anti-goals

- No Build 41 support (different codebase, shrinking audience).
- No replacement of `BaseVehicle` and no override of the scripts' gear ratios: both cause BCP's conflicts and
  its modded-car problems. Anything we add must work from numbers a script already has.
- No copied BCP code or tables. The behaviours are common driving physics; the implementation is ours.
- Anti-goal: a change that makes an ordinary drive feel worse for someone who does nothing. Every new effect is
  sandbox-controlled, and the defaults must keep a normal drive close to 0.1.19.

## Design

**A. Two-way coupling (the core).** In the engine section of the controller, when the geared wheel speed is
above engine speed with the driven wheels in contact:
- pull engine RPM toward the geared wheel RPM (clutch drag), which gives rev-match on a downshift and keeps
  the RPM tracking road speed when you lift off;
- add a retarding force at the driven wheels equal to the engine's friction and pumping torque times the gear
  ratio, scaled by a sandbox `EngineBraking` strength, clamped well below the tyre grip limit so it cannot lock
  the wheels by itself;
- if the geared RPM would exceed about 1.15 x redline (a downshift that is far too low), let the retarding
  force reach the grip limit for a moment: the lock-up slide, gated by its own option.
Calibrate off game with the headless bullet bench first (as the torque curve was), then in game.

**B. RPM profiles.** Read the redline and shift point from the vehicle's `engineRPMType` for the four vanilla
types (generic, firebird, jeep, van) instead of two hard-coded values, with the current numbers as the fallback
for any unknown type. Modded cars that name a vanilla type get its character for free.

**C. Install status.** One line in the vehicle info panel and in the log: ZombieBuddy active / manual classes
active / Java part missing. A missing Java part (the subscription alone) shows once as an in-game notice.

**D. Languages.** Add JSON translations (the only form 42.20+ reads) for DE, PT-BR, TR, FR, ES, ZH. Machine
drafts, reviewed by commenters before release.

**E. Engine sound (stretch, spike first).** Prove in one day that a looping, RPM-pitched clip plays from the
vehicle emitter in 42.21 on the existing path, then generate one or two engine/exhaust loops (fal.ai, licence
safe) and ship them as the first `engineSound` specs. If the spike fails, drop E from 0.2.

Each of A's effects and B has a sandbox option; presets set them. All of it runs in the client physics, as
today, so servers still need no Java.

## Test plan

New automated modes next to `ki5`/`rules`: `coast` (lift off at 80 km/h in each gear, measure deceleration and
that RPM tracks road speed), `downshift` (rev-match, and the lock-up only for a too-low gear), `profiles` (each
`engineRPMType` redlines where its profile says). Regression: sp, mp, msc, wheels, ki5, others, rules. Every
mod change is verified in game in SP and on a local dedicated server before release, as for 0.1.x.

## Calls I made (change any of them)

- Engine braking defaults to **on** at a modest strength, because it is the headline of the release; the
  alternative is off-by-default and a preset.
- Lock-up slide defaults to **off**.
- Sound stays a stretch behind a spike, not a promise.
